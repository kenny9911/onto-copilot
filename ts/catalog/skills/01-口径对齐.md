# 口径对齐
> 将同一属性、指标或规则在多个来源中的定义拆到可比较轴，区分真实冲突与信息缺失并形成待决策项

## 何时用
两个及以上来源看似描述同一业务含义，但在范围、计量、时间、聚合或取值边界上
无法同时成立时使用；只有名称不同但含义未确定时走实体对齐，只有一侧未说明时
走缺口追问，不把缺失误报为冲突

## 步骤
1. 建立比较记录，保留左右两侧原文、`evidence_id`、`文件名!位置`、关联对象或
   属性稳定 ID；没有定位信息的内容不得进入裁决选项。
2. 逐轴抽取明确写出的取值：
   - **业务范围**：对象、组织、人员、地区、状态和适用场景；
   - **计量口径**：含税/不含税、单位、币种、汇率日和舍入方式；
   - **时间口径**：业务发生日/记账日、生效期、粒度、统计窗口和时区；
   - **聚合口径**：单笔/累计、去重方式、分母、是否含取消或冲销记录；
   - **边界口径**：大于/大于等于、空值、例外和默认值；
   - **权威来源**：规则层级、版本和生效日期。
3. 只比较两侧都明确写出的轴，分类为 `CONFIRMED_CONFLICT`、
   `POSSIBLE_CONFLICT` 或 `MISSING_REQUIRED`；名称相同不是冲突证据，名称不同
   也不是无冲突证据。
4. 用 `oir.query` 查关联稳定 ID；需要原始上下文时用 `evidence.search` 和
   `evidence.rows`，不要凭截断片段补全轴值。
5. 对真实冲突从以下方案中给出适用的 2~4 个，而不是机械凑满四个：保留为两个
   属性、统一为 A、统一为 B、抽成上下文参数或业务必填项。每个方案写明信息损失、
   影响对象、可逆性和所需决策人。
6. **不替业务方选择方案。** 没有足够证据时形成 question，说明需要谁提供哪份
   定义或哪个业务示例。

## 完成判据
- 每条比较记录都有左右原文、证据定位和关联稳定 ID
- 缺失、可能冲突和已确认冲突没有混写
- 冲突明确指出具体轴和值，不使用“口径不一致”作为唯一结论
- 每个解决方案都有证据、影响范围和可逆性说明
- 没有静默统一口径或替业务方作决定

## 工具
evidence.search、evidence.rows、oir.query
