# Skill catalog

一项 Skill 一个 Markdown，数字前缀决定内置注册顺序。Skill 是可验收的领域操作规程，
不是背景知识文章，也不是自由发挥的角色提示词。

运行时读取以下章节：

```markdown
# Skill 名称
> 一句话描述

## 何时用
正向触发条件；容易混淆时同时写明不适用边界

## 步骤
可执行规程：先证据和确定性检查，再语义判断，最后路由问题或决策

## 完成判据
- 可由产物、计数、状态或引用验证的检查项

## 工具
tool.one、tool.two

## 标签
少量且有区分度的检索词
```

## 编写约束

- `>` 描述必须保持单行；解析器只读取第一条引用行。
- `description` 与“何时用”常驻技能目录；步骤、完成判据和工具按需加载。
- 运行时会在每份 Skill 前注入统一执行边界：Skill 不能扩大 Agent 的任务、工具、
  输出 schema 或变更权限；Agent/node 契约优先。
- 关键禁令、升级条件和输出约束必须写进“步骤”或“完成判据”，不能只放在描述或标签。
- “何时用”同时说明正向触发和最容易误用的相邻 Skill，避免职责重叠。
- 步骤使用命令式动作，并写清输入证据、工具用途、分类结果、停止条件和缺口路由。
- 能确定性检查的内容先检查；模型只处理规则难以表达的语义判断。
- 完成判据必须可复核，避免“结果合理”“内容完整”“符合要求”这类宽泛表述。
- 工具名必须登记在 `../tools/tools.yaml`，并且属于所有引用该 Skill 的 Agent
  `tool_scope` 的交集。仅列工具名不够，步骤中还要说明何时以及为何调用。
- Skill 不得要求输出 Agent schema 中不存在的字段。无法承载但会影响交付的信息，
  明确写入现有 `questions`、`gaps`、`conflicts`、`warnings` 或 blocker message；
  不得自行扩展模型输出。
- 当 question/gap 的 schema 只接受字符串时，用包含优先级、应答角色、被阻塞产物、
  回答格式和 evidence ID 的紧凑文本，不输出对象。
- 标签只影响 `select()`，不会显示在已加载正文里；标签过多会稀释当前 Jaccard 分数，
  应优先使用名称、业务同义词和典型材料类型。

## 维护检查

修改 Skill 后至少检查：

1. H1 名称与 Agent `skills` 引用一致。
2. “何时用”“步骤”“完成判据”非空。
3. 工具存在且对所有引用 Agent 可用。
4. 指令能由当前 Agent output schema 承载，或已明确路由到现有缺口字段。
5. 与相邻 Skill 的触发边界清楚。
6. 更新 `golden/skills.json` 并运行 catalog、kernel 和全量测试。
