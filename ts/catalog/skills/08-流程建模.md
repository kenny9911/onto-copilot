# 流程建模
> 将访谈与材料转换成角色完整、异常可达且与证据和数据对象共用稳定 ID 的流程模型

## 何时用
需要建立或修订 AS-IS/TO-BE 流程，或现有材料只有步骤清单、缺少角色、条件、异常
和输入输出语义时使用；不用于单独的数据血缘或 ERP 字段映射

## 步骤
1. 先在分析中固定流程边界、建模粒度和 `AS_IS` 或 `TO_BE` perspective；两种
   perspective 必须分开输出，未经确认的建议不得进入 AS-IS。当前 schema 不承载
   边界或版本时不要新增字段，影响建模的缺失写入 `gaps`。
2. 用 `evidence.search`、`evidence.rows` 和 `oir.query` 提取触发、执行角色、
   动作、前置条件、输入/输出 DataObject、系统和证据。步骤名使用“动词 + 业务对象”，
   每个节点使用稳定 ID。
3. 建立有向边，明确 `SEQUENCE`、`CONDITIONAL`、`EXCEPTION`、`TIMEOUT` 和
   `CANCEL`；条件边写可判断条件，异常边写触发事件。不要把异常、取消和人工介入
   塞进备注。
4. 不把并行关系伪装成顺序。当前输出 schema 无法表达并行 split/join 或独立 gateway
   时，在 `gaps` 写明 `SCHEMA_CAPABILITY_GAP`、涉及步骤和所需语义，不制造错误流程。
5. 检查开始节点、正常结束、异常结束、孤立节点、悬空引用、循环退出条件和所有分支
   可达性；边引用的步骤和数据 ID 必须存在。
6. 用 `impact.trace` 检查步骤与 Action、Event、DataObject、Rule 和 ERP mapping
   的关联；缺少关联时形成 gap，不虚构对象。
7. 结构化流程是唯一真相源，可视化图必须从同一组节点、边和稳定 ID 生成，不单独
   维护第二份流程内容。

## 完成判据
- 整份输出只使用一个明确的 AS-IS 或 TO-BE perspective
- AS-IS 与 TO-BE 没有混写
- 每个步骤都有稳定 ID、角色、输入输出、系统和证据
- 条件、异常、超时、取消和人工介入已显式表达
- 无法表达的并行或 gateway 已进入 gap，而非错误串行化
- 无孤立节点、悬空边和不可退出循环
- 结构化输出与可视化使用完全相同的 ID

evidence.search、evidence.rows、oir.query、impact.trace
