# 命名归一
> 在不改变来源标识和业务语义的前提下生成 lowerCamelCase 规范名，并记录冲突、影响和回滚信息

## 何时用
canonical apiName 缺失或不符合命名规范，出现空格、下划线、大驼峰、中文、数字
前缀、保留字或未登记缩写时使用；不得用命名相似度替代实体对齐，也不得自动改写
已发布的外部接口标识

## 步骤
1. 先确认对象、属性、动作等命名空间，以及术语表、批准缩写、保留字和已发布契约；
   原始物理名和外部名称始终保留为 source name 或 alias。
2. 只有满足以下全部条件时才自动修复：分词唯一、语义不变、缩写已登记、目标名合法、
   同命名空间无碰撞、没有外部契约影响。
3. 对空格、下划线和大小写做确定性转换，例如 `plan_amount`、`Plan Amount` →
   `planAmount`；稳定 ID 不随 displayName 或 apiName 改变。
4. 中文、未登记缩写、音译、多义词、数字前缀和标点导致的歧义不得猜测。只有术语表
   存在精确映射时才可自动采用，否则输出建议并交人确认。
5. 用 `oir.query` 做同命名空间碰撞和引用检查；用 `evidence.search`、
   `evidence.rows` 或 `profile.column` 核对来源字段。碰撞时不通过添加随机后缀
   掩盖问题。
6. 生成改名账：稳定 ID、来源名称、建议名称、触发规则、状态、受影响引用和回滚值；
   自动修复标 `AUTO_REPAIRED`，待确认项标 `REVIEW_REQUIRED`。

## 完成判据
- 来源名称、alias 和稳定 ID 均未丢失
- 自动修复均满足可逆、无歧义、无碰撞和无外部契约影响
- 中文和未登记缩写没有被机器猜译
- 每处变化都有 from、to、理由、状态和回滚记录
- 已检查保留字、同命名空间碰撞和引用完整性

## 工具
evidence.search、evidence.rows、oir.query、profile.column
