# 回传审核
> 对业务方回传模板做身份对齐、确定性校验、语义复核和责任人级打回，计算可信完成度

## 何时用
收到业务方填写或确认后回传的模板时使用；不用于新材料抽取，也不替代向外发布前
的交付审查

## 步骤
1. 先读取已有确定性审核结果；已有结果时不要让模型重复计算。若尚未执行，先校验
   template ID、版本、sheet 结构、必需列和可用的模板 manifest/hash。
2. 按 `_oir_rid` 对齐，不按行号。识别缺失、重复、伪造或无法匹配的锚点，以及
   插行、删行、移动列和系统列被修改。
3. 用 `_oir_hash` 区分原样预填和实际修改。AI 预填原样交回只在存在明确确认标记时
   算已确认；没有确认标记则记为 `UNREVIEWED_PREFILL`。
4. 确定性检查优先：必填、类型、枚举、命名、引用、公式、主键、受保护列和跨表
   完整性。可由 `model.lint` 或代码判断的内容不得交给模型自由发挥。
5. 语义模型只复核已收窄的口径冲突和疑似敷衍候选，并保留候选原文、上下文和判断
   理由；无法排除合理填写时不要误伤。
6. 完成度仅以业务必填格为分母，使用版本化权重，并分别统计 `CONFIRMED`、
   `COMPLETED`、`MISSING`、`INVALID`、`UNREVIEWED_PREFILL` 和
   `NOT_APPLICABLE`。
7. 打回项按具体责任人分组，包含 issue code、位置、当前值、期望格式、证据、截止
   时间和被阻塞产物；不得静默修改业务方原始回传。

## 完成判据
- 模板版本、结构和锚点完整性已经校验
- 行对齐完全基于 _oir_rid，而不是显示顺序
- 原样预填与明确确认已被区分
- 确定性问题没有重复交给模型判断
- 完成度的分母、权重和各状态数量可复算
- 每个打回项都有具体责任人、问题位置和修正标准
- 原始回传文件保持不变且审核结果可追溯
