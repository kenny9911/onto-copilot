# OntoCopilot 工具与 Agent 工作流清单

> 这份文档回答两个问题：**AI 手上有哪些工具**、**这些工具被编排成了哪些工作流**。
>
> 判断标准是"跑起来是什么样"，不是"设计成什么样" —— 每一条都标了成熟度，
> 定义了但没人调用、或者恒返回定值的，一律照实写。

---

## 一、工具：AI 手上有什么

工具按**作用域**授予，不是全局可用。这是间接提示注入的主要防线：材料内容再怎么
诱导，抽取节点的动作空间里根本没有出网工具。危险级别决定要不要人点头
（`EXTERNAL` 一律需要确认，见 `tools.py` 的 `requires_approval`）。

### 1.1 内核工具（`kernel/tools.py`，抽取与对话共用）

| 工具 | 作用 | 危险级 | 谁能用 |
|---|---|---|---|
| `evidence.search` | 按关键词检索材料切片，返回 `{cite, text}`。**找不到时返回现有文件列表而不是空数组** —— 空结果会让模型断言"材料里没有" | READ | 全部 |
| `evidence.rows` | 按位置取原文（某表第 30~46 行）。行号不是关键词，`search` 找不到它 | READ | 全部 |
| `oir.query` | 查已抽出的对象/属性/关系/行动，避免同一个概念抽两遍 | READ | 全部 |
| **`impact.trace`**〔本轮新增〕 | **改这一个东西会牵动哪些别的东西。** 给名字或 rid，返回受影响项、路径、层数 | READ | 全部 |
| `profile.column` | 某一列的确定性统计（唯一率、空值率、推断类型、样本）。跨行分布问题不该靠看样本猜 | READ | 抽取/对齐/分析 |
| `code.exec` | 沙箱内跑一段数据变换代码 | COMPUTE | **仅** analyze/compile |

`code.exec` 刻意不给读客户材料的 agent —— 材料是不可信输入，一段伪装成业务说明
的指令就能诱导模型调它。

### 1.2 对话工具（`server.py`，FDE 直接对话时可用）

**只读（工作模式 + 聊天模式都给）**

| 工具 | 作用 |
|---|---|
| `material.list` | 有哪些材料、各读进来多少段。三档状态刻意分开：已解析 / 待识别 / 未读 |
| `material.parse` | 把某份材料读进索引（不产出任何产物，所以聊天模式也给） |
| `material.inspect` | 看一份材料的结构：几张表、各是什么形状 |
| `material.rows` | 列出某张表的原始行，**绕开索引的采样上限**直接读文件 |
| `session.status` | 当前进度：材料、产物统计、待拍板、建议、花费 |
| `flow.query` / `flow.issues` | 查流程图节点 / 查图上的病灶（死路、无标签分支、无事件动作） |
| `template.query` | 查已编译的填写模板 |
| `ui.table` | 把一批数据画成表格给用户看（返回给模型的是摘要，不是全部行） |
| `export.file` | 把聊天里的任意内容导成可下载文件 |

**改产物（仅工作模式，每个都必须回显改了什么）**

| 工具 | 作用 |
|---|---|
| `oir.add` / `oir.edit` / `oir.undo` | 口述的事实进本体，一律标人工来源；可撤销 |
| `flow.edit` / `flow.undo` / `flow.preview` | 改流程图 / 撤销 / 预览 |
| `template.edit` / `template.undo` / `template.recompile` | 改模板 / 撤销 / 重出 |
| `decision.record` | 记一条口径或命名的约定，之后每个抽取节点都带着它 |
| `suggestion.apply` | 采纳一条建议 |
| `build.start` | 开跑梳理 |

## 二、Agent 工作流：这些工具被编排成了什么

### 2.1 主流水线（材料 → 本体）

真正花钱跑模型的那条。阶段：

```
PARSE     解析材料、切片、建索引、出列画像          纯规则
  ↓
EXTRACT   按 sheet/章节切段 → fan-out 成多个抽取节点   规则腿 + 模型腿
          · 规则能定的先逐行抽（登记表、行动表、问卷）
          · 剩下的交给模型，节点内是 agent loop 不是单次调用
          · CoverageCritic 拦"看起来跑完了其实什么都没抽到"
  ↓
MERGE     多段产物合并成一份 OIR                   纯规则
  ↓
ALIGN     同义实体对齐。**合并不可逆，所以拿不准的一律不合**  纯规则
  ↓
CONFLICT  八类冲突检测（口径分歧、命名违规、重复、敷衍…）   五类纯规则
  ↓
GAP       挖缺口：空表、未定槽位、枚举不全、结构空位      纯规则
  ↓
FINISH    自动修 → 澄清排序 → 编译模板                纯规则
  ↓
EXPORT    产物落盘、交付包                          纯规则
```

**关键设计**：付费的模型理解只发生在 EXTRACT 一处，下游全部确定性。所以重跑、
撤销、回放都不用再花钱。

### 2.2 对话推理循环（FDE 问一句话）

每一轮都进推理循环，规则判定降级成提示塞进 prompt。三种推理方式按"路径可不可
枚举"选：

- **直接回答** —— 不需要查任何东西（寒暄、常识、就事论事的解释）
- **边查边想（ReAct）** —— 要查、但查什么取决于上一步看到什么
- **先列计划再执行** —— 目标明确、步骤当场能列全（"把 X 连到 Y，然后重出模板"）

三条纪律由结构保证，不靠提示词自律：工具只给只读作用域、答案里每个出处都必须
来自工具返回（编的当场删掉）、推理过程流式可见。

### 2.3 FDE Engagement DAG（九阶段交付编排）

`INTAKE → INTERVIEW → PROCESS → ERP_MAP → RULES → DATA_OBJECTS → GAP →
CANONICALIZE → REVIEW → EXPORT`

**现状要说清楚**：调度、checkpoint、人工确认、release gate 都是真的在跑，
但六个专业 agent（interviewer / process_modeler / erp_mapper / rule_engineer /
data_steward / delivery_reviewer）目前是**确定性投影，不调模型** ——
`implementation_kind` 恒 UNKNOWN、`stakeholders` 恒空。

难看，但至少不会编。接模型之前必须先有金标，否则没有任何办法判断第二轮材料理解
是变好还是变坏。

### 2.4 Critic（把关的那一层）

- `RuleCritic` —— 规则判定，只有 HIGH 才算不通过
- `LLMCritic` —— 语义判定，**必须用与生成者不同的模型**（异构评委，缓解自我增强偏差）
- `CoverageCritic` —— 行覆盖：112 行的表只抽出 8 条，这就是静默失败的形态

## 三、本轮改动

### 新增：`impact.trace`

FDE 一天问很多次"这个能不能改""改了影响多大"。图一直在 OIR 里，但没有任何遍历
出口 —— 产品只能说不知道。

纯图遍历、零模型，所以这条链路上**不存在编造**：返回的每个 rid 必然是 OIR 里
已有的实体（有测试断言这个集合包含关系）。接受中文名/apiName/rid 三种写法 ——
逼模型先查一次 rid 是白多一轮往返，而且它会开始猜 rid 的构造规则。

### 修好：三处"系统看出来了但没说"

**① 口径认不出维度时不再沉默**

轴表只有四条采购财务轴。换个行业（工艺、条款、诊疗）一条都命中不了，于是两段
内容完全不同的口径拿到同一个签名、被判成同一种，直接跳过。

**这不是"没查出来"，是主动判定了"这两条口径相同"** —— 全仓库唯一一处系统把两个
不同判断当成同一个，同时踩了「查不到就说查不到」和「口径不自行统一」两条纪律。

现在：认得出维度就报维度；认不出就报**差在哪几个字**，并明说这一维判不出来。
字面完全相同时仍然不报（不是把静默换成噪声）。

**② 客户自带的问题不再挤掉系统自己挖的**

`mine_questions` 的 limit 以前把客户问卷也算进名额。而 extra 在生产里是客户问卷
＋流程图缺口，随便一份材料就顶满 60 —— 于是"系统发现材料里缺什么"这件事**一条都
进不来，且悄无声息**：空表、未定槽位、枚举缺失全被饿死。

现在 limit 只约束我们自己挖的那部分。

**③ 对齐拿不准的那些对有了出口**

对齐引擎的保守是对的（合并不可逆，假阳性最贵），但 `uncertain` 以前没有任何
消费者：只进了一条事件载荷和 CLI 打印。系统比对上千对、看出来了，然后什么也没说。

尤其是登记表段产出的对象**天生零属性**，这类对象之间的相似永远拿不到结构证据、
永远沉默 —— 连别名字面完全相同的两个对象也是这个下场。

现在转成问题进 backlog，带着双方出处和"凭什么这么问"。**出口是"问一句"，
不是"替他决定"** —— 合并仍然要人点头。

## 四、还没做的（按价值排序）

1. **拿 3-5 份真实客户材料跑一遍 `infer_shape`** —— 比下面任何一条代码改动都便宜。
   仓库里只有一份真材料，所有涉及"属性表"的收益估计在现有证据上都不成立。
2. **抽取的金标集** —— 在给任何东西"接真模型"之前。零标注就能先加的一条：
   同一份材料跑两遍，OIR 的 api_name 集合 Jaccard ≥ 0.95。
3. **溯源 gate** —— locator 回查不中要抬成 HIGH。"每条结论能点回原文"这条纪律
   今天在抽取节点上没有强制点。
4. **静默丢弃变可见丢弃** —— 三处 `continue`（属性无宿主、关系两端查不到、
   中文名过长）无计数无 finding。丢了多少必须说出来。
5. **`package.diff`** —— revision 字段齐全，但全库无 diff 函数。
6. **答完问题之后的下游链条** —— 回答事务本身扎实，但下游什么都不发生。
