### 1 号要单独说：**我上午的修复只修了一半，而且把响的错变成了闷的错**

上午修的 A0 是 `YIELD_CN` 缺 `links` 导致 `KeyError` 崩掉整个抽取 run。
补上枚举之后崩溃没了 —— 但 `check()` **根本没读 `draft["links"]`**，
`outstanding()` 收到的 `have.links` 恒为 `undefined`，于是一律当成"零关系"。

结果：**崩溃变成了「永远判失败」**。抽得好好的那份被打成不合格，
精炼循环还会反复重试。**崩是响的，永远失败是闷的，闷的那种更贵。**
两处必须一起修，现在两条测试分别钉住「缺关系要报」和「有关系不许报」。

## 四、右栏：设计得不合理的地方

### blocker

**R1｜右栏没有任何「改」的入口。**
属性表把口径摆出来给你核对，却改不了。整个右栏能写字进输入框的只有两处：
缺口小标（6 句预置）和「询问此对象」。
FDE 扫到 `estimatedAmount / DECIMAL / 预估采购金额`，凭经验知道客户这个字段不含税 ——
界面到此为止。他得把手移到输入框，**把对象名、属性名、要改的字段全部重敲一遍**
（敲错一个字模型就改到别的对象上），发出去，等一轮 LLM，再滚回右栏重新找到这个对象、
重新展开属性表、重新核对。
**核对的产物一定是修正，而这个产品把修正做成了重新打字。**
→ 属性行加行内动作，点了预填一句已经带全 rid + apiName + 当前值的指令，人只补结论。

**R2｜440px 默认宽度下，点开任何一处证据或画布，整个模型列表被卸载。**
实测：选中第 3 项、筛选切到「对象」→ 点「在画布中打开」→ 列表 unmount →
返回后详情回到第 1 项、筛选复位「全部」。
split 视图要 ≥680px 才启用，而右栏默认 440px。
**「看断言 → 翻出处 → 回来接着核对下一条」是 FDE 的标准动作，现在每翻一次出处就丢一次位置。**
→ 把 `selectedId` / `kind` 提到 `ContextSidebar` 层（改动很小）。

**R3｜审阅详情的「影响范围」「证据对照」两节在真实数据上永远不渲染。**
两节都是 `{x.length ? … : null}`，而实测 196 条真实问题 **applies 非空 0 条、evidence 非空 0 条**。
FDE 回答一条问题时，屏幕上**没有任何线索说这会改哪个对象**，只能凭记忆。
评审签字必须落在具体实体上，否则决定记了也追不回模型。
→ 两节改成常驻，空态说下一步，并给一个「指定影响对象」的写入入口。

### major

**R4｜规则 / 流程 / Event 三类根本不计算缺口，于是最空的三类在界面上显得最完整。**
`gaps: []` 三处硬写死。而真实库里这三类恰恰最空：40 条规则全是一句自由文本、
Event 全无载荷、流程图有死端。FDE 现在照着芯片挑活 —— **没有芯片 = 不在工作队列 = 永远轮不到。**

**R5｜列表行上没有一个能区分彼此的信号。**
缺口在 `modelItems` 里**已经逐项算好**，却只在详情里画。
「哪些对象缺主键」这个 FDE 最想要的工作队列，只能一条一条点开看 ——
而答案是 527/527 全缺。再叠上 80 条硬截断：202 个对象的会话有 122 条**点不到**。
→ 行右侧画 `gaps.length`，按缺口数排序，筛选加一档「待补全 N」。数据现成，零后端改动。

**R6｜大模型跑完一轮，右栏一个字都不说变了什么。**
数字在光标底下自己变了，没有高亮、没有 diff、没有「本轮新增 X」。
模型回「已补充 6 个属性」，右栏可能显示 3 个（另外 3 个挂到别的对象上了）——
**这个差他看不出来，除非把刚花十分钟做完的核对重做一遍。**

**R7｜「在画布中打开」对对象是个空动作。**
画布默认工作流模式，切到「对象关系」那一下的 `onClick` 里带着 `setSelectedId("")`，
**刚传进来的选中项当场被清掉**。流程项更彻底：`process:${key}` vs 画布的 `workflow:${key}`，前缀就对不上。

**R8｜「查看出处」打开整份文件、不定位到那一条 cite。**
而隔壁 `preview.ts` 的 `openSource` 干的正是这件事：`querySelector([data-cite])` →
`scrollIntoView` → 加描边。**定位能力就在仓库里活着，新路径没接。**

**R9｜流程详情的三个数字：一个恒等于另一个、一个恒为 0。**
实测 35 个节点 grounded 全 false、objects 全空 → 「无直接依据节点」永远等于「节点」、
「业务对象」永远是 0。而 `flow.stats` 里躺着**真正能指导动作**的数字一个都没上屏：
`terminals: 0, dead_ends: 2`（这张图没有终态、有两个死端）。

**R10｜搜索框承诺「文件、对象、流程、规则」，实际是四个互不相干的本页筛选。**
在交付页搜「采购申请」显示「还没有产物」——FDE 会判定没有，而模型页里明明有这个对象。

### minor

- **8 个空态里 6 个只说「暂无」**。其中「当前筛选下没有模型项」在整个 OIR 为空时也是这句 ——
  把「还没建模型」说成「筛选没匹配上」，FDE 会去改筛选而不是传材料。
  而画布在完全相同的处境下给的是「从通用场景生成草案」按钮 —— **同一个 App 两种待遇**。
- **「证据」节排在「待确认」前面**，而证据 100% 为空 —— 今天要处理的东西被一行永远没用的灰字压到一屏之外
- **「询问此对象」把半句话冲掉**（`mode: "replace"`），换成一行元数据引用，还露出 `ot_a` 这种内部 rid、管业务对象叫「画布节点」
- **缺口小标互相覆盖**：一个对象四个缺口，点第二个把第一个冲掉
- **「记录决定」会把输入框已有内容替换掉并立刻发出去**
- **窄屏没有任何断点**：990px 以下整个应用横向滚动，右栏被推到屏幕外
- 审阅队列唯一区分等级的是一颗 `aria-hidden` 色点，而默认筛选让它全列同色；副标题逐字重复分组表头
- 项目页 hero 第二枚徽标是后端运行态 `idle` 原样回显；算好的 revision 从不显示

### 9.2 会话记忆：先证明它确实没有

不是凭感觉说「记忆不够」，是量出来的：

```
真实库 11 个会话：dialogue.decisions 全部 = 0
其中 bafd0dd05e69 有 _oir_patch_log（3 次 add_batch，真发生过编辑）
project_memory 表：0 行     decision / decision_record / revision_record：全 0
```

### 9.3 做了什么

| 件 | 内容 |
|---|---|
| **`memory_log`** | 一条会话记忆流：`seq / kind / what / **basis** / refs / tool`。落进 `PERSISTED`，重启还在。封顶 500 条 |
| **写入点** | `oir.add`/`oir.edit`（**两条分支都记**）、`flow.edit`（原来一条不记）、`flow.undo`（撤销也是改动，不记的话记忆里那条看着像还生效）、`draft.adopt`、`suggestion.apply`、`decision.record` |

| **`memory.recall`** | 返回分成「项目记忆」（跨会话长期档）和「本次会话」两段。键从 `命中` 改成 `项目记忆` —— 叫「命中」时读的人分不出手里这条是长期结论还是刚才顺手改的 |

**两条设计纪律**：

1. **改了就记，不在写入侧筛。** 判断「这条重不重要」是导出和召回的事；

## 十一、传图重画 bug 一族（用户实测上报，同日）

用户传了一张业务流程图 PNG 要求「根据这个图重新画一张」，得到的却是一张
无关的通识模板图。逐层查下来是**四个缺陷串成的链**，每一环都修了：

### ① 结构性死锁：轮内启动永远失败（blocker）✅修

工作模式的聊天轮**全程持有 mutation 租约**，轮内工具去 `claimBuildLease` 会被
**本轮自己的租约**挡掉（`claimBuildLease` 见到未过期 mutation 租约一律拒绝）——
重试一万次也一样。两条回执还各说各话：`flow.preview` 谎报「已经在跑了。」、
`build.start` 说「会话状态是 idle」启动不了 —— 模型拿着互相矛盾的回执，
只能退去画通用模板。

**修法**：轮内抢不到且状态可启动 → 登记 `_start_build_after_turn`，
**本轮租约释放后立刻兑现**（dialogue.ts 轮末执行，失败发事件 ——
回执承诺了"回完立刻启动"，静默不启动就是回执撒谎）。full 不被 preview 降级覆盖。
`flow.preview` 的回执拆成三种情况分开说。

### ② readiness 看不见图片 OCR（major）✅修

`proseHits` 只扫**零标签或 heading** 的切片，而 OCR 切片全带
`['ocr','title'/'paragraph'/'note']` 标签 —— **整份图片的文字被排除在所有
正文信号之外**。写满「采购需求计划流程」的图，六维全判「没有」→ NOT_ENOUGH。

**修法**：判据从「零标签」改成「**不带结构化标签**」（schema/table/column/fk/…）。
OCR 正文算弱信号（score 1）—— 它确实不如流程文档，但绝不是零。

### ③ 重画不用材料里的环节名（major）✅修

图片进不了抽取管线（`flow_extract` 是固定格式正则），但 OCR 文本就在 `_chunks`
里躺着 —— `flow.sketch` 却从不看它，凭 domain 两个字画通识。

**修法**：sketch 前扫会话切片，流程相关的节选（≥5 条才算）喂进 prompt：
「环节名、阶段名**优先用材料里出现的原词**；材料没提的连接才用通识补，
补的进 caveats」。`semanticInput` 带 `grounded` 标记 —— 重放指纹能区分接地版
和纯通识版。**披露不降级**：连线仍有推断成分，产物照旧标参考图。
工具描述同步改写 —— 原来还写着「材料已上传就不要用它」，恰好把这个场景推开。

### ④ SVG 单模板（用户点名）✅修

`SVG_TEMPLATES` 四档：classic（默认米色，老图字节不变）/ slate（深底投屏）/
print（黑白打印，灰阶也分得开）/ blueprint（蓝图冷调）。
**模板只换配色不换布局** —— 有测试钉着「剥掉颜色后四个模板的 SVG 完全一致」。
认不出的模板名回落 classic 并**说出来**，不让用户以为换了没生效。

新增 **16 条测试**（死锁排队 3、readiness OCR 2、sketch 接地 2、SVG 模板 5、
flow.preview 三分支重钉 + full 优先 + build.start 排队…）。
全量 **6499 passed / 6 failed**（6 条仍是另一会话在途）。服务已带新构建重启。
