# 用例集

单元测试钉的是**函数的行为**，用例钉的是**产品的行为**。两者会在不同的地方失败：

- 313 个单元测试全绿，但上传一份真实 xlsx 之后什么都抽不出来 —— 这种事发生过三次。
- 每一次的根因都不是某个函数写错了，是**几个正确的部件拼在一起产生了错误的整体**：
  段渲染把同一段话重复 22 遍、问卷被判成实体表、critic 判错方向导致重试到烧穿预算。

所以用例的判据全部是**用户能观察到的事实**：抽出了多少对象、模板有几张表、
问一句话能不能答上来、重启之后还在不在。不检查内部数据结构。

## 跑

```bash
# 全部（会真的调模型，有成本，每条用例标了预估）
.venv/bin/python usecases/run.py

# 只跑不花钱的
.venv/bin/python usecases/run.py --free

# 指定几条
.venv/bin/python usecases/run.py UC-01 UC-07
```

需要服务器在 `127.0.0.1:8000` 上跑着。用例自己建会话、自己清理。

## 清单

| 编号 | 名字 | 花钱 | 钉住的失败 |
|---|---|---|---|
| UC-01 | 上传即可提问 | 否 | 曾经必须先花 $3 跑完抽取才能问第一个问题 |
| UC-02 | 问卷不是实体表 | 否 | 150 行澄清问题被抽成 150 个 ObjectType |
| UC-03 | 登记表一行不丢 | 否 | 168 行实体只抽出 58 个 |
| UC-04 | 合并单元格不撑爆段 | 否 | 一行 22 列同值 → 27 万字符 → 模型放弃整段 |
| UC-05 | 会话重启后还能用 | 否 | 重启后打开旧会话，所有操作 409 |
| UC-06 | 会话删除干净 | 否 | 删了还在列表里 / 删了产物也没了 |
| UC-07 | 对话推理带出处 | 是 ~$0.3 | 模型编出处，FDE 拿去翻材料翻不到 |
| UC-08 | 编造的出处会被删掉 | 否 | 附一句"可能有误"把核对推给用户 |
| UC-09 | 意图分流 | 否 | 判不出意图 = 反问，而不是去查 |
| UC-10 | 采纳建议真的改产物 | 是 ~$3 | 点了"采纳"，产物纹丝不动 |
| UC-11 | 梳理中插话不丢 | 是 ~$3 | 排了队但永远不执行 |
| UC-12 | 口径约定进抽取节点 | 是 ~$3 | "我记下了"是空话，节点看不见 |

花钱的用例默认跳过，`--paid` 才跑。
